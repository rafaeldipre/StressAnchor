Create a Go network stress testing tool with two independent binaries:
`stress-server` runs on OCI, and `stress-client` runs on an Orange Pi 5 or another on-premise Linux host.

The tool is intended to validate a Cloudflare Mesh site-to-site network path.

STRESS-SERVER
Target: linux/amd64 for Ubuntu Server on OCI.

Required listeners:

- TCP `:9000`: echo server that returns exactly the bytes it receives.
- UDP `:9001`: echo server.
- HTTP `:8080` with these endpoints:
  - `GET /ping`: returns `{"status":"ok","ts":<unix_ns>}`.
  - `POST /data`: receives a request body and returns its size in bytes.
  - `GET /stats`: returns the current server statistics as JSON.
  - `GET /`: serves an HTML dashboard that refreshes every second.
  - `GET /metrics`: exports Prometheus-compatible text metrics.

The server must track these in-memory statistics with a mutex:

- `total_connections`
- `active_connections`
- `bytes_received`
- `bytes_sent`
- `requests_per_second`, calculated every second
- `errors`
- `uptime_seconds`
- `per_protocol` counters for TCP, UDP, and HTTP

The dashboard must be fully inline in Go, with no external dependencies.

Startup flags:

```sh
--host 0.0.0.0 --port-tcp 9000 --port-udp 9001 --port-http 8080
```

STRESS-CLIENT
Target: linux/arm64 for Orange Pi 5.

Required flags:

- `--host`: server IP address in OCI, for example `10.175.0.5`
- `--workers`: number of concurrent workers, default `50`
- `--duration`: total test duration in seconds, default `60`
- `--mode`: `tcp`, `udp`, `http`, or `mixed`, default `mixed`
- `--payload-size`: payload size in bytes per request, default `1024`
- `--ramp-up`: seconds to reach the full worker count, default `5`
- `--report-interval`: reporting interval in seconds, default `2`

Client behavior:

- Start workers gradually during the ramp-up period.
- Each worker sends requests continuously until the test duration ends.
- In `mixed` mode, distribute workers as 40% TCP, 30% UDP, and 30% HTTP.
- In TCP mode, connect to `--host:9000`, send the payload, read the echo, and measure RTT.
- In UDP mode, send a datagram to `--host:9001`, wait for the response, and measure RTT.
- In HTTP mode, send `POST /data` with a body of `--payload-size` bytes and measure latency.

Client metrics:

- Latency p50, p95, p99, max, and min in milliseconds
- Latency histogram buckets
- Requests per second
- Sent and received MB/s
- Total error count and error rate
- Active workers
- Elapsed and remaining time

Terminal output:

- Update a metrics table every `--report-interval` seconds.
- Repaint the terminal instead of scrolling.
- Use aligned columns and ANSI colors when supported:
  - green for OK
  - yellow for p95 latency above 100 ms
  - red for errors or p95 latency above 500 ms

When the test finishes:

- Print a complete summary.
- Save a JSON report as `stress_report_<timestamp>.json`.
- Save a CSV report as `stress_report_<timestamp>.csv`.
- The CSV file should contain one row per reporting interval.

Project structure:

```text
mesh-stress-test/
+-- cmd/
|   +-- server/main.go
|   +-- client/main.go
+-- internal/
|   +-- stats/
|   +-- proto/
+-- Makefile
+-- README.md
```

Makefile targets:

- `make build-server`
- `make build-client`
- `make cross-server`: builds `bin/stress-server-linux-amd64`
- `make cross-client`: builds `bin/stress-client-linux-arm64`

Restrictions:

- Use only the Go standard library.
- The server must not require root privileges.
- The client must handle context cancellation and `SIGINT`/`SIGTERM` cleanly.
- The client must always save the report, even when interrupted.
- Use idiomatic Go with handled errors, goroutines coordinated with `sync.WaitGroup`, and no data races.
- Linux support is required; Windows and macOS support is optional.
